# Неинициализированная shared memory в Vina-CUDA_v1.1

**Результат.** Редукция в `gyration_radius_update` читает хвост shared-массивов, который функция не инициализирует. На H100 при одинаковых аргументах измерения и разных предварительных состояниях памяти получены радиусы `1` и `2.465413` для 55 атомов. После патча оба варианта дают эталон `1`. Это потенциальный источник недетерминизма; естественный разброс запусков приложения с фиксированным seed не воспроизводился.

## 1. Условия проверки

- Область: `Vina-CUDA_v1.1`, upstream `HPCLab-933/Vina-CUDA`, исходный коммит `7b09586a64025d06c854a63eee21268fba5bc8f0`.
- Стенд: NVIDIA H100 PCIe, cc 9.0, драйвер 580.105.08, CUDA Toolkit 12.8, g++ 13.3, Ubuntu 24.04. 
- Путь по умолчанию (`rilc_bfgs = 1`): `kernel2_update` (8192 блока по 32 потока) → `mutate_conf_cl_update` при выборе поворота → `gyration_radius_update`.
- `--seed` задаёт CPU-генератор случайных карт и стартовых поз, но не инициализирует shared memory. При сравнении приложения также фиксируются параметры, сборка, GPU и порядок лигандов.

## 2. Причина и исправление

В [mutate_conf.cuh](Vina-CUDA_v1.1/inc/cuda/mutate_conf.cuh) массивы `acc` и `counter` имеют по `MAX_NUM_OF_ATOMS = 128` элементов. Исходная функция обнуляет и заполняет только `[0, m_lig_end)`, затем суммирует все 128 элементов. Хвост читается без предварительной инициализации этим вызовом. Лиганды с `m_lig_end ≥ 128` приложение отвергает, поэтому хвост есть при любом допустимом размере.

Правильный радиус — `sqrt(Σd² / N_heavy)`, где расстояния считаются от переданного origin, а водороды исключаются. Посторонние значения в сумме и счётчике могут изменить радиус, дать ноль или NaN. Радиус используется в `amplitude / R_g`, поэтому ошибка может менять поворот, траекторию поиска и итоговые позы. Например, радиус `2.465413` вместо `1` уменьшает масштаб поворота примерно до 40,6% правильного.

Исправлена только граница обнуления; цикл чтения атомов сохраняет границу `m_lig_end`:

```diff
 for (int i = threadNumInBlock;
-    i < m_lig_end;
+    i < MAX_NUM_OF_ATOMS;
     i = i + threadsPerBlock)
```

Каждый поток обнуляет свои индексы `t + 32k`; перед совместной редукцией уже есть `__syncthreads()`. Дополнительный барьер для этой правки не нужен.

## 3. Эксперимент и наблюдения

[Тест](Vina-CUDA_v1.1/tests/gyration_shared_init/test_gyration.cu) вызывает настоящую функцию без изменений её тела. Один блок из 32 потоков делает два вызова с барьером между ними:

1. **Подготовка памяти:** вызов на 128 атомах полностью записывает массивы. Все атомы — либо H (нулевой шаблон), либо тяжёлые на расстоянии 3 (отношение суммы к счётчику равно 9, включая частичные суммы редукции).
2. **Измерение:** `m_lig_begin = 0`, размер `n`; тяжёлые атомы на расстоянии 1, каждый четвёртый атом — H на расстоянии 5. CPU-эталон в `double` равен 1. Атомы за границей `n` находятся на расстоянии 7, чтобы ошибочное включение их вкладов было заметно.

Подготовка на 128 атомах укладывается в массивы теста, но приложение такой размер отвергает. Она задаёт состояние памяти; переиспользование памяти между блоками не моделируется.

`run_test.sh` собирает один тест с сохранённым исходным заголовком из `tests/gyration_shared_init/baseline/` (точная копия upstream-коммита `7b09586a64025d06c854a63eee21268fba5bc8f0`) и с заголовком рабочего дерева. История upstream и доступ к сети для изолированного теста не нужны. Сохранены [логи H100](Vina-CUDA_v1.1/tests/gyration_shared_init/results_h100/).

| Шаблон памяти | n | CPU-эталон | Исходная версия | Исправленная |
|---|---:|---:|---:|---:|
| Нулевой | 16, 31, 32, 55, 127 | 1 | 1 | 1 |
| Ненулевой | 16 | 1 | 2.905488 | 1 |
| Ненулевой | 31 | 1 | 2.729764 | 1 |
| Ненулевой | 32 | 1 | 2.720294 | 1 |
| Ненулевой | 55 | 1 | 2.465413 | 1 |
| Ненулевой | 127 | 1 | 1.04042 | 1 |

В каждом случае все 32 потока вернули побитово одинаковое конечное значение. Исходные результаты совпали с моделью редукции в пределах допуска `1e-5 × max(1, |expected|)`, а также во всех напечатанных знаках. Для `n = 55` имеется 42 тяжёлых атома и 73 элемента хвоста: `sqrt((42 + 73 × 9) / (42 + 73)) ≈ 2.465413`.

Исходный бинарник вернул 1 из-за ожидаемых расхождений, исправленный — 0. Скрипт проверил все случаи; итоговый код — 0. Ошибка CUDA, отсутствие результата или неожиданный код этих бинарников не принимаются за ожидаемый дефект.

## 4. Границы выводов

- **По коду:** функция читает неинициализированный ею хвост массивов.
- **На H100:** управляемое изменение предыстории памяти при одинаковых аргументах измерения меняет радиус; патч устраняет эту зависимость во всех проверенных случаях.
- **Не проверено:** естественное изменение состояния памяти между одинаковыми запусками приложения, вызванный им разброс поз и энергий, стабильность всего приложения после патча.

Происхождение начального содержимого памяти не установлено. Разный порядок блоков сам по себе не доказывает разброс: при фиксированном `n < 32` нулевой хвост остаётся нулевым при повторении редукции — вклады переносятся от больших индексов к меньшим.

**Ограничения среды.** Локальная среда — Mac без доступной NVIDIA CUDA GPU; выполнить CUDA-проверку локально невозможно. Доступ к стороннему GPU-серверу ограничен по времени и ресурсам, поэтому на H100 выполнен только изолированный CUDA-тест. Полное приложение не собиралось и не запускалось; установка Boost и длительные прогоны докинга не выполнялись. Это ограничение доступной среды и охвата проверки, а не установленная ошибка сборки. В соответствии с пунктом 3 задания команды сборки и сценарий повторных запусков с фиксированным seed для подходящей среды приведены в разделе 5.

Compute Sanitizer 2025.1.0.0 на сервере не поддерживает `initcheck` для shared memory: **SKIP**, инструментального подтверждения нет.

## 5. Повторение проверки

Команды ниже выполняются из корня репозитория `Vina-CUDA`. Для изолированного теста нужны Linux, NVIDIA GPU и CUDA Toolkit; `sm_90` соответствует H100. Указать доступный GPU:

```bash
GPU_INDEX=0
CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES="$GPU_INDEX" \
NVCC=/usr/local/cuda/bin/nvcc CUDA_ARCH=sm_90 \
    bash Vina-CUDA_v1.1/tests/gyration_shared_init/run_test.sh
```

Коды: `0` — ожидаемый дефект исходной версии и прохождение исправленной; `1` — несоответствие ожиданиям; `2` — ошибка; `77` — пропуск. На H100 основная проверка прошла, sanitizer — SKIP.

Для информационного сравнения полных запусков подготовлен [repro_app.sh](Vina-CUDA_v1.1/tests/app_determinism/repro_app.sh). Нужны две сборки приложения и Boost (в Makefile указан 1.77):

```bash
git clone https://github.com/HPCLab-933/Vina-CUDA.git ../vina-base
git -C ../vina-base checkout --detach 7b09586a64025d06c854a63eee21268fba5bc8f0
# Подготовить Boost: ./bootstrap.sh; ./b2 --with-program_options --with-system --with-filesystem --with-thread
# В Makefile обеих копий задать WORK_DIR (каталог Vina-CUDA_v1.1),
# BOOST_LIB_PATH и NVCC_COMPILER; выполнить make source в Vina-CUDA_v1.1.
BASE_BIN=../vina-base/Vina-CUDA_v1.1/Vina-GPU-2-1-CUDA \
FIXED_BIN=Vina-CUDA_v1.1/Vina-GPU-2-1-CUDA \
    RUNS=5 SEED=42 Vina-CUDA_v1.1/tests/app_determinism/repro_app.sh
```

Сценарий не запускался. Он сравнивает повторы внутри каждой версии по PDBQT, энергиям первой позы и координатам. Каждый лиганд — отдельный процесс; пакетный режим не проверяется. `STABLE` означает совпадение сохранённого вывода, а не отсутствие других дефектов. Равенство версий не требуется.
