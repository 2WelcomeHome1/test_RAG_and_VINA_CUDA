# Тестовое задание: Senior AI Engineer — RAG

**Время:** 4–6 часов. Создайте запускаемый через Docker Compose RAG API и предложите план его развития.

## Что должно работать

Поддерживаемые файлы до 5 MiB: TXT, Markdown, Word (DOCX), PDF с текстовым слоем, XLSX, PPTX. Оригиналы хранятся в MinIO, текст и embeddings — в PostgreSQL/pgvector. API отвечает на вопросы по всему корпусу с цитатами из контекста.

| Запрос | Наблюдаемый результат |
|---|---|
| `POST /v1/documents` — multipart `file` | `201`: `document_id`, `filename`, `chunks_count`; оригинал и чанки сохранены. |
| Ошибка ingest | `413` — >5 MiB; `415` — формат не поддержан; `422` — пустой, повреждённый или без текста; `503` — S3/embedding недоступен; `500` — ошибка БД. |
| `POST /v1/query` — `{"query":"..."}` | `200`: ответ и до 5 цитат с точным текстом и ссылкой на документ/чанк; место в источнике указано, где доступно (страница, ячейки, слайд, раздел). |
| Пустой корпус / query | Пустой корпус: `200`, `Недостаточно информации в загруженных документах.`, пустые citations. Пустой query: `422`; ошибка AI: `503`. |

## Проверяемые результаты

- Compose поднимает `rag-api`, PostgreSQL/pgvector, MinIO; API доступен на `0.0.0.0:8000`. Миграция создаёт таблицы и векторный индекс.
- Приёмочные тесты проверяют каждый формат, сохранность байтов, ошибки/пустые файлы, отсутствие частичных строк и rollback с best-effort удалением S3-объекта.
- Query-тесты проверяют пустой корпус/запрос, поиск факта не из последнего документа, grounded-ответ, точность цитат и лимит 5. Отдельно проверяются параллельный ingest и схема pgvector.
- Платные AI API не нужны: Compose использует детерминированные провайдеры; сбои проверяются тестовыми подменами. Тестовый endpoint запрещён.
- Для каждого приёмочного теста показать целевой мутант, который этот тест обнаруживает; выживших мутантов быть не должно.
- README описывает запуск и риск аварии между S3 upload и commit в БД, содержит Mermaid-схему встраивания в корпоративный контур (системы, границы и потоки данных, безопасность, мониторинг) и план из 2–3 приоритизированных улучшений с ценностью и шагами реализации.

## Запуск и сдача

Сдать Compose, Dockerfile, `.env.example`, код, миграции, README и API-тесты. В образ `rag-api` включить pytest; тесты запускаются в контейнере:

~~~sh
cp .env.example .env
docker compose up --build -d
docker compose exec -T rag-api pytest -q
docker compose exec -T rag-api python -m scripts.mutation_check
~~~

Для очистки: `docker compose down`; с локальными данными: `docker compose down -v`. Задание принято, если стек запускается и перечисленные проверки автоматизированы либо отмечены как требующие интеграционной среды.
